# XAI literature matrix: what exists and what we can test on the gate

**Our setup, for the "fit" column:**
- **Access:** only output probabilities (execute, ask, refuse), with no gradients or internals.
- **Data:** 1,433 test calls with seven fields each, 123 of them multi-turn.
- **Models:** five vendor models; only gpt is deterministic, and gpt refuses some reduced inputs.
- **Gate:** certified thresholds (Learn-then-Test), so a call's route depends on threshold crossings, not on the top label.

**Fit symbols:** ✅ usable as is · 🔧 usable with a change we have to make · ❌ needs access we don't have.

With all 23 papers read, the gaps hold. None explains a **threshold crossing or a reject decision for text inputs**: LLiMe [14] comes closest but explains a binary label, and Artelt [08, 20, 21] explains rejects but only for numeric data. None explains **uncertainty through concept edits**. ConformaSight [11] fills the certificate column for tabular columns; doing the same for **text fields** of a certified gate is open. This is still not a proof that nothing exists elsewhere.

**Rules that apply to all tests:**
- Never use the decision model's own explanations as ground truth (07).
- Re-check every LLM-generated edit against the real model (05, 06).
- Log generator refusals as their own outcome, because safety training shapes generators (04).
- Keep concepts free of label leakage (13).
- Always report a simple baseline such as matching (15).
- Use repeats or hierarchical pooling for the stochastic models (18).

**Suggested start:** T1–T3 and T9 cost nothing; T1–T3 settle our existing attribution findings, T9 extends the certificate-level line. T4 is the cheapest way to try the "symbiosis". T7/T8 address the gap and need a query budget; plan them with Nijat first.
